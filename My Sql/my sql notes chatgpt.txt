               Tables, Constraints & Keys (Deep Explanation)
1️⃣ What is a Table?

Table = Structure used to store data inside database.

A table contains:

Rows → Records

Columns → Fields

Example: Employees Table

emp_id	name	salary	dept
101	Mk	50000	IT

Here:

emp_id, name, salary, dept → Columns

Each row → One employee record

2️⃣ How to Create a Table?

Syntax:

CREATE TABLE table_name (
    column_name datatype,
    column_name datatype
);

Example:

CREATE TABLE employees (
    emp_id INT,
    name VARCHAR(50),
    salary DECIMAL(10,2)
);

Meaning:

INT → Integer number

VARCHAR(50) → Text up to 50 characters

DECIMAL(10,2) → Decimal number

3️⃣ What is Constraint?

Constraint = Rule applied on a column.

It controls:

What type of data allowed

What not allowed

Example:
If emp_id must not be duplicate → use constraint.

🔑 TYPES OF KEYS (Very Important)
1️⃣ Primary Key

Primary Key:

Uniquely identifies each row

Cannot be NULL

Cannot be duplicate

Example:

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50)
);

Why important?

If 2 employees have same emp_id → confusion.

So primary key ensures uniqueness.

2️⃣ Foreign Key

Foreign Key:

Used to create relationship between tables

Refers to primary key of another table

Example:

Departments Table:

CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

Employees Table:

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50),
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
);

Meaning:
employees.dept_id must exist in departments table.

3️⃣ Unique Key

Unique Key:

No duplicate values allowed

But NULL allowed (sometimes depending on DB)

Example:

CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE
);

Two users cannot have same email.

4️⃣ Composite Key

Composite Key:
Primary key made using 2 or more columns.

Example:

CREATE TABLE student_marks (
    student_id INT,
    subject_id INT,
    marks INT,
    PRIMARY KEY (student_id, subject_id)
);

Here:
Combination of student_id + subject_id must be unique.

5️⃣ Candidate Key

Candidate Key:
All columns that can become primary key.

Example:

If:

emp_id unique

email unique

Both are candidate keys.
But only one becomes primary key.

6️⃣ Super Key

Super Key:
Any combination of columns that uniquely identifies row.

Example:

emp_id

emp_id + name

emp_id + salary

All are super keys.
But minimal one is candidate key.

📌 Important Constraint Types
NOT NULL

Column cannot store NULL value.

name VARCHAR(50) NOT NULL
DEFAULT

Gives default value.

salary INT DEFAULT 10000
CHECK

Condition must be satisfied.

salary INT CHECK (salary > 0)

1️⃣ DDL – Data Definition Language

DDL = Structure create & modify panna use pannuvom.

It works on:
👉 Tables
👉 Database structure

Important:
DDL commands automatically commit (rollback panna mudiyadhu usually).

DDL Commands:
🔹 CREATE

Used to create database or table.

CREATE DATABASE company;
CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50),
    salary INT
);
🔹 ALTER

Used to modify table structure.

Add column:

ALTER TABLE employees
ADD department VARCHAR(50);

Modify column:

ALTER TABLE employees
MODIFY salary DECIMAL(10,2);

Drop column:

ALTER TABLE employees
DROP department;
🔹 DROP

Deletes entire table permanently.

DROP TABLE employees;

⚠ Data also deleted permanently.

🔹 TRUNCATE

Deletes all rows but keeps table structure.

TRUNCATE TABLE employees;

Difference:
TRUNCATE is faster than DELETE.
Cannot rollback normally.

2️⃣ DML – Data Manipulation Language

DML = Used to work with data inside table.

🔹 INSERT

Add data into table.

INSERT INTO employees (emp_id, name, salary)
VALUES (101, 'Mk', 50000);

Insert multiple rows:

INSERT INTO employees VALUES
(102, 'Arun', 40000),
(103, 'Ravi', 35000);
🔹 SELECT

Retrieve data.

SELECT * FROM employees;

Select specific columns:

SELECT name, salary FROM employees;
🔹 UPDATE

Modify existing data.

UPDATE employees
SET salary = 60000
WHERE emp_id = 101;

⚠ Without WHERE → all rows update aagum.

🔹 DELETE

Delete rows.

DELETE FROM employees
WHERE emp_id = 101;

Without WHERE:
All rows delete aagum 😬

3️⃣ DCL – Data Control Language

DCL = Permissions manage panna use pannuvom.

🔹 GRANT

Give permission.

GRANT SELECT ON employees TO user1;
🔹 REVOKE

Remove permission.

REVOKE SELECT ON employees FROM user1;
4️⃣ TCL – Transaction Control Language

TCL = Control transactions.

Transaction = Group of SQL statements executed together.

🔹 START TRANSACTION
START TRANSACTION;
🔹 COMMIT

Save changes permanently.

COMMIT;
🔹 ROLLBACK

Undo changes.

ROLLBACK;
🔹 SAVEPOINT

Create checkpoint inside transaction.

SAVEPOINT sp1;

Rollback to savepoint:

ROLLBACK TO sp1;
🔥 DDL vs DML Difference (Interview)

              Filtering & Sorting Data (Deep Explanation)

Filtering = Specific rows choose panna
Sorting = Order la arrange panna

1️⃣ WHERE Clause

WHERE is used to filter rows based on condition.

Syntax:
SELECT column_name
FROM table_name
WHERE condition;
Example:
SELECT * FROM employees
WHERE salary > 40000;

Meaning:
Show employees whose salary is greater than 40000.

2️⃣ Comparison Operators
Operator	Meaning
=	Equal
>	Greater than
<	Less than
>=	Greater or equal
<=	Less or equal
<> or !=	Not equal

Example:

SELECT * FROM employees
WHERE department != 'HR';
3️⃣ AND Operator

Used when multiple conditions must be TRUE.

SELECT * FROM employees
WHERE department = 'IT'
AND salary > 40000;

Both conditions must be satisfied.

4️⃣ OR Operator

At least one condition must be TRUE.

SELECT * FROM employees
WHERE department = 'IT'
OR department = 'HR';
5️⃣ BETWEEN

Used for range values.

SELECT * FROM employees
WHERE salary BETWEEN 30000 AND 50000;

Includes both 30000 and 50000.

6️⃣ IN Operator

Used to match multiple values.

Instead of writing:

WHERE department = 'IT'
OR department = 'HR'

We write:

SELECT * FROM employees
WHERE department IN ('IT', 'HR');

Cleaner and better.

7️⃣ LIKE Operator

Used for pattern matching.

Used with:

% → Any number of characters

_ → Single character

Starts with:
SELECT * FROM employees
WHERE name LIKE 'M%';

Names starting with M.

Ends with:
SELECT * FROM employees
WHERE name LIKE '%k';

Names ending with k.

Contains:
SELECT * FROM employees
WHERE name LIKE '%ar%';

Name containing “ar”.

8️⃣ ORDER BY (Sorting)

Used to sort result.

Ascending (default):
SELECT * FROM employees
ORDER BY salary;
Descending:
SELECT * FROM employees
ORDER BY salary DESC;
9️⃣ LIMIT (Important in MySQL)

Used to restrict number of rows returned.

SELECT * FROM employees
LIMIT 5;

Returns first 5 rows.

With offset:

SELECT * FROM employees
LIMIT 5 OFFSET 5;

Skip first 5 rows, show next 5.

Used in pagination.

🔥 Real Life Example

E-commerce site:

"Show top 10 products under 5000 sorted by price"

SQL:

LIMIT 10;

         Aggregate Functions + GROUP BY + HAVING
1️⃣ What is Aggregate Function?

Aggregate function means → Multiple rows ah eduthu one single value return pannum.

Example:

100 employees salary irukku

SUM(salary) → 1 total amount return pannum

2️⃣ Important Aggregate Functions
Function	Meaning
COUNT()	Number of rows
SUM()	Total value
AVG()	Average value
MIN()	Smallest value
MAX()	Largest value
🔹 COUNT()
SELECT COUNT(*) FROM employees;

Meaning:
Total number of employees.

🔹 SUM()
SELECT SUM(salary) FROM employees;

Total salary amount.

🔹 AVG()
SELECT AVG(salary) FROM employees;

Average salary.

🔹 MIN() & MAX()
SELECT MIN(salary), MAX(salary)
FROM employees;

Lowest and Highest salary.

⚠ Important Rule

Aggregate functions always return single value (unless GROUP BY used).

3️⃣ GROUP BY (Very Important)

GROUP BY is used to group rows with same values.

Example situation:

emp_id	name	department	salary
1	A	IT	40000
2	B	HR	30000
3	C	IT	50000
4	D	HR	35000
Question:

Department wise total salary?

SQL:
SELECT department, SUM(salary)
FROM employees
GROUP BY department;
Output:
department	SUM(salary)
IT	90000
HR	65000

👉 GROUP BY means:
“Same value irukkura rows ah group pannitu calculation pannum”

4️⃣ Important Rule of GROUP BY

If you use GROUP BY:

Every column in SELECT must be:

Either aggregate function

OR included in GROUP BY

Wrong:

SELECT name, SUM(salary)
FROM employees
GROUP BY department;

❌ Error.

Correct:

SELECT department, SUM(salary)
FROM employees
GROUP BY department;
5️⃣ HAVING Clause

HAVING is used to filter grouped data.

Remember:

WHERE → filters rows
HAVING → filters groups

Example:

Department wise total salary greater than 80000:

SELECT department, SUM(salary) AS total_salary
FROM employees
GROUP BY department
HAVING SUM(salary) > 80000;
🔥 WHERE vs HAVING (Clear Difference)
WHERE	HAVING
Filters rows	Filters grouped result
Used before GROUP BY	Used after GROUP BY
Cannot use aggregate	Can use aggregate
Execution Order of SQL (Very Important for Interview)

FROM

WHERE

GROUP BY

HAVING

SELECT

ORDER BY

LIMIT

Remember this order da 🔥

🧠 Real World Example

E-commerce site:

“Show departments where average salary > 40000”

SELECT department, AVG(salary)
FROM employees
GROUP BY department
HAVING AVG(salary) > 40000;
💡 Interview Question

Because WHERE cannot use aggregate functions like SUM(), AVG().

3️⃣ Window Functions (Very Very Important)

Window function = Row by row calculation without collapsing rows.

Unlike GROUP BY → it won’t reduce rows.

🔹 Example – Rank employees by salary
SELECT name,
       salary,
       RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;

👉 Highest salary → rank 1

🔹 ROW_NUMBER()
SELECT name,
       salary,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num
FROM employees;

Difference:

RANK() → Same salary na same rank
ROW_NUMBER() → Always unique number

🔹 Partition By (Most Important)

Department wise rank:

SELECT name,
       dept_id,
       salary,
       RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS dept_rank
FROM employees;

👉 Each department separate ah ranking.

🔥 Window vs GROUP BY
GROUP BY	Window Function
Rows reduce aagum	Rows reduce aagathu
One value per group	Row by row calculation
Basic aggregation	Advanced analytics
💡 Data Engineering Use

Window functions use pannuvanga:

✔ Top N records

✔ Latest record find pannurathuku

🔹 Running Total Example

📘 1️⃣ Running Total (Cumulative Sum) – Deep Explanation
Example Table:
emp_id	name	salary
1	A	1000
2	B	2000
3	C	3000
4	D	4000
🔹 Query:
SELECT emp_id,
       name,
       salary,
       SUM(salary) OVER (ORDER BY emp_id) AS running_total
FROM employees;
🔥 Output:
emp_id	salary	running_total
1	1000	1000
2	2000	3000
3	3000	6000
4	4000	10000

👉 Explanation:

Row 1 → 1000
Row 2 → 1000 + 2000
Row 3 → 1000 + 2000 + 3000
Row 4 → All sum

📘 2️⃣ Partition + Running Total

Department wise running total:

SELECT dept_id,
       name,
       salary,
       SUM(salary) OVER (PARTITION BY dept_id ORDER BY emp_id) AS dept_running_total
FROM employees;

👉 Each department separate calculation.

📘 3️⃣ Window Frame (Advanced Concept 🔥)

By default:

RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW

Meaning:
From first row till current row.

🔹 Custom Window Frame Example

Last 2 rows sum:

SELECT emp_id,
       salary,
       SUM(salary) OVER (
           ORDER BY emp_id
           ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
       ) AS last_two_sum
FROM employees;

👉 Logic:

Current row + previous row only.
